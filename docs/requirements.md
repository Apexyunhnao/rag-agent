# 需求文档 — 客服售后政策问答 Agent（RAG Agent）

## 业务背景

电商客服场景里，政策类问题占咨询量的大头：退货要什么条件、退款几天到账、换货运费谁出、偏远地区多久送到。这些规则分散在多份制度文档中，客服需要翻文档找答案，口径还容易不一致——同一条退货规则，不同人说法可能不一样。

本项目的假设场景：某电商平台有一套售后政策文档。用户用自然语言提问，系统直接返回**带出处的答案**，而不是一个文档链接。回答末尾必须标 `[来源: 文档名]`，让提问的人能自己核对。

## 目标

把预置政策文档向量化存入 ChromaDB，用户提问 → 检索 Top-5 最相关片段 → LLM 合成带来源引用的回答。

核心流程：
1. 文档预置（ingest）：加载 → 分块（300 字，重叠 50）→ 向量化 → 入库
2. 用户提问 → 问题向量化 → ChromaDB 检索 Top-5
3. 片段 + 来源元数据 → LLM 合成回答（附 `[来源: 文档名]`）

## 成功指标

| 指标 | 定义 | 目标 |
|------|------|------|
| 检索命中率 | Top-5 片段中包含目标文档的比例 | ≥ 90% |
| 回答准确率 | 回答命中预期关键词的比例 | ≥ 85% |
| 来源正确率 | 回答标注的 `[来源: 文档名]` 与目标文档一致的比例 | 100% |
| 回答耗时 | 从请求到返回完整答案的时间 | ≤ 5 秒 |

## 功能范围

### MVP 包含
- 预置 4 份客服售后政策文档（退货 / 退款 / 换货 / 物流配送）
- 单轮问答：提问 → 返回带来源引用的回答
- HTTP API（FastAPI）：`POST /query`
- 演示页面：`GET /` 内置单文件 HTML 页面
- 查询日志：问题、来源、回答摘要、耗时写入 SQLite
- 评估脚本：20 条用例（16 训练 + 4 留出）跑检索命中率 / 回答准确率 / 来源正确率

### MVP 不包含
- 多轮对话（单轮够用，先验证 RAG 管道质量）
- 文档权限管理
- 用户登录 / 鉴权
- Prompt 注入防护

## 文档清单

预置文档（中文 Markdown，放在 `data/documents/`）：

1. **退货政策.md** — 退货条件、流程、运费、特殊商品
2. **退款政策.md** — 到账时间、退款路径、差价退款
3. **换货政策.md** — 换货条件、时效、运费、与退货的区别
4. **物流配送政策.md** — 发货时效、预售商品、偏远地区、快递查询

## 非功能性要求

- Embedding 走本地 CPU（`BAAI/bge-small-zh-v1.5`，512 维），不依赖外部 API
- LLM 走 DeepSeek 兼容接口（openai SDK，不锁厂商）
- 每个模块有类型标注和中文注释，方便快速读懂

## 版本说明（v1 → v2）

v1 的知识库是企业办公文档（员工手册、IT FAQ 等 5 份），用于验证「检索 + 引用溯源」这条链路能跑通。

v2 把知识库整体重构为电商售后政策 4 份文档，并同步重建测试集、切留出集、统一评估口径。理由是业务链路：本项目负责「政策怎么答」（RAG），客服工单 Agent 负责「工单怎么办」（工具调用编排），两者由上游 supervisor 串成一条完整的客服链路。
